# 🚀 DNS Manager — Hybrid DoH для OpenWrt

**DNS Manager** — менеджер DNS-конфигурации для OpenWrt, построенный вокруг гибридной схемы:

**LAN → dnsmasq :53 → несколько локальных DoH-инстансов → рабочий ответ**

и отдельного DNS-маршрута для российских зон:

**`.ru` / `.su` / `.рф` → отдельный RU DNS**

> [!IMPORTANT]
> DNS Manager работает на уровне DNS. Он не заменяет полноценные средства DPI-обхода, VPN, прокси и туннели. Для DPI-блокировок и других методов фильтрации DNS может быть недостаточно; такие решения могут использоваться параллельно.

---

## ✨ Основная идея

Главная задача менеджера — не заставить пользователя вручную настраивать десятки параметров, а:

1. **Сначала прочитать реальное состояние роутера.**
2. Найти уже установленные DNS, DoH, прокси, VPN, Zapret и другие решения.
3. Понять, какие настройки принадлежат DNS Manager, какие являются чужими, а какие неизвестны.
4. Проверить доступные DNS-серверы.
5. Выбрать подходящий профиль автоматически.
6. Показать пользователю **конкретный план изменений**.
7. После подтверждения применить изменения одной транзакцией.
8. Проверить результат.
9. При ошибке выполнить автоматический откат изменений текущей транзакции.

Менеджер предназначен прежде всего для **грязных роутеров**, на которых уже что-то установлено и настроено вручную.

# 🧠 Архитектура

## 🚀 Hybrid DoH

Классический профиль проекта использует несколько DoH upstream одновременно через локальные экземпляры `https-dns-proxy`.

Упрощённо:

```text
                         INTERNET
                            │
                 ┌──────────┴──────────┐
                 │      HTTPS / DoH     │
                 └──────────┬──────────┘
                            │
          ┌─────────────────┼─────────────────┐
          │                 │                 │
       DoH #1            DoH #2            DoH #3
       DoH #4            DoH #5            DoH #6
          │                 │                 │
          └─────────────────┼─────────────────┘
                            │
                      dnsmasq :53
                            │
                           LAN
```

Базовая концепция проекта — **несколько независимых DoH-серверов**, чтобы отказ одного сервера не означал отказ всей DNS-инфраструктуры.

В классическом Hybrid-профиле используются логические слоты:

```text
DoH 1
DoH 2
DoH 3
DoH 4
DoH 5
DoH 6
RU DNS
```

Конкретные локальные порты назначаются менеджером с учётом уже занятых портов. Если стандартный порт занят сторонним сервисом, DNS Manager не должен отнимать его у этого сервиса — выбирается другой свободный порт.

# 🇷🇺 RU / SU / РФ Split

Для российских доменов предусмотрен отдельный маршрут:

```text
.ru
.su
.рф
```

→ отдельный RU DNS.

Идея:

```text
Обычный домен
      │
      ▼
  6 DoH upstream
      │
      ▼
   ответ

.ru / .su / .рф
      │
      ▼
   RU DNS
```

Это позволяет не заставлять весь трафик использовать один и тот же DNS-профиль и уменьшает вероятность проблем с российскими локальными сервисами.


## 🔄 Автоматическая проверка обновлений

`dns-manager.sh` — единственная постоянная точка входа.

При каждом запуске рекомендуется проверять GitHub на новую версию:

```text
/usr/bin/dns-manager
        │
        ├── прочитать установленную версию
        │
        ├── проверить GitHub
        │
        ├── новой версии нет
        │       └── запустить текущую
        │
        └── новая версия есть
                │
                ├── скачать во временный файл
                ├── проверить загрузку
                ├── проверить, что это DNS Manager
                ├── проверить версию
                ├── выполнить sh -n
                ├── сохранить предыдущую версию
                ├── атомарно заменить рабочий файл
                └── запустить новую версию
```

### 🛡 Безопасное обновление

Рабочий файл не должен удаляться до успешной проверки новой версии.

Правильный порядок:

```text
GitHub
  ↓
/tmp/dns-manager.new
  ↓
проверка
  ↓
sh -n
  ↓
резерв текущей версии
  ↓
атомарная замена
  ↓
запуск
```

Если GitHub недоступен или новая версия не прошла проверку:

```text
🟡 Новую версию получить не удалось.

Текущая версия сохранена.
Конфигурация роутера не изменена.
Запускается установленная версия.
```

### ↩ Предыдущая версия

Перед заменой рекомендуется сохранять:

```text
/usr/bin/dns-manager.previous
```

чтобы при несовместимости можно было вернуть предыдущий менеджер.

### ⚙ Политика обновлений

В настройках менеджера следует предусмотреть:

```text
🟢 Проверять обновления и предлагать установку
🟡 Только уведомлять
🔴 Не проверять
```

По умолчанию:

```text
🟢 Проверять
🟡 Устанавливать только после подтверждения
```

### 📌 Важно

**Обновление программы не изменяет конфигурацию DNS.**

Обновляется только:

```text
/usr/bin/dns-manager
```

Настройки роутера изменяются отдельно, через обычный цикл:

```text
Discovery
   ↓
Plan
   ↓
[✓] Применить
   ↓
Snapshot
   ↓
Apply
   ↓
Verify
   ↓
✓ успех
или
✗ rollback
```

### 🚫 Одноразовый запуск через process substitution не является основным способом

Не рекомендуется постоянно запускать:

```sh
sh <(wget -O - ...)
```

Основной способ:

```sh
dns-manager
```

Это позволяет:

- контролировать версию;
- безопасно проверять обновление;
- сохранять предыдущую версию;
- избежать проблем `Broken pipe`;
- запускать уже проверенную локальную копию;
- отдельно контролировать обновление программы и изменение конфигурации роутера.

# 🔐 TLS и CA-сертификаты

DoH работает по HTTPS, поэтому на роутере должны быть корректные корневые сертификаты.

DNS Manager проверяет наличие:

- `ca-certificates`;
- `ca-bundle`;
- системного CA-хранилища.

Если CA отсутствуют, менеджер **не должен отключать проверку TLS через `-k` / `--insecure`**.

Вместо этого пользователь должен получить понятное сообщение:

```text
✗ CA-сертификаты не найдены

HTTPS/DoH нельзя безопасно проверить.

Необходимо установить:
✓ ca-certificates
или
✓ ca-bundle
```

Это особенно важно на минимальных сборках OpenWrt.

# 🌐 Каталог DNS

Менеджер использует большой каталог DoH-серверов.

Каталог нужен не для того, чтобы одновременно запускать все серверы.

Его задача:

```text
Большой каталог
      │
      ▼
   Живой тест
      │
      ▼
Рабочие DNS
      │
      ├── 🚀 обход / community
      ├── 🌍 геоблокировки / сервисы
      ├── 🎮 игры
      ├── ⚡ чистые
      ├── 🛡 безопасность
      ├── 🔐 приватность
      ├── 🧹 adblock
      └── 👨‍👩‍👧 family
      │
      ▼
  выбор 6 активных
```

### Почему категории важны

**Быстрый DNS не обязательно является DNS для обхода блокировки.**

Поэтому менеджер не должен делать выбор только по задержке.

Для автоматических профилей учитываются:

- результат теста;
- доступность DoH;
- время ответа;
- стабильность;
- назначение;
- категория;
- регион;
- дубли;
- возможность использовать DNS как резерв.

# 🚀 Максимальный обход

Это основной быстрый режим для пользователя, который не хочет разбираться в DNS.

В меню:

```text
🚀 МАКСИМАЛЬНЫЙ ОБХОД
```

Менеджер:

1. читает конфигурацию роутера;
2. тестирует каталог;
3. исключает серверы, которые не прошли тест;
4. исключает дубли;
5. отделяет специальные/региональные DNS;
6. подбирает до 6 рабочих серверов;
7. добавляет отдельный RU-маршрут;
8. проверяет порты;
9. показывает пользователю план;
10. применяет только после `✓ ДА`;
11. выполняет финальную проверку.

### Важно

DNS Manager **не обещает обход абсолютно всех видов блокировок**.

DNS может быть полезен при:

- DNS-подмене;
- DNS-фильтрации;
- некоторых геоограничениях;
- региональных DNS-маршрутах;
- специальных DNS-сервисах.

Но DNS не является универсальной заменой:

- DPI-обходу;
- IP-обходу;
- VPN;
- прокси;
- туннелям;
- изменению сетевой маршрутизации.

Для DPI-профилей проект можно использовать вместе с [Zapret](https://github.com/bol-van/zapret).

# 🛡 Совместимость с Zapret

DNS Manager и Zapret решают разные задачи.

Условная схема:

```text
DNS Manager
    │
    ├── DNS
    ├── DoH
    ├── dnsmasq
    ├── TLD split
    └── NTP

Zapret
    │
    ├── DPI
    ├── desync
    ├── firewall
    └── сетевые правила
```

Менеджер должен:

- видеть наличие Zapret;
- не удалять его UCI;
- не перезаписывать его конфигурацию;
- учитывать его firewall-правила;
- учитывать `force_dns`;
- не пытаться забрать занятый сторонний порт.

Если обнаруживается сторонний `force_dns`, пользователь получает предупреждение:

```text
⚠ Обнаружен сторонний force_dns.

DNS-трафик клиентов может перехватываться
сторонним DoH.

TLD split и балансировка dnsmasq
могут работать не так, как ожидается.
```

# 🔍 Тест DNS

Тест должен отвечать не только на вопрос:

> «порт 443 отвечает?»

а на вопрос:

> «это действительно рабочий DoH endpoint?»

Поэтому тест учитывает:

1. разрешение имени;
2. HTTPS/TLS;
3. корректность HTTP-ответа;
4. DNS-ответ;
5. время ответа.

Для DoH необходимо учитывать разные варианты реализации endpoint. Сервер не должен считаться неисправным только из-за того, что он не принимает конкретный неуниверсальный способ тестирования.

# 🎯 Bootstrap DNS

Bootstrap нужен для первого разрешения DoH hostname.

Логика:

```text
Роутер загрузился
      │
      ▼
время + базовая сеть
      │
      ▼
Bootstrap DNS
      │
      ▼
разрешение DoH hostname
      │
      ▼
HTTPS / DoH
```

Bootstrap должен быть максимально независимым от самого DoH-пула.

Можно выбирать:

```text
[✓] Независимый набор
[✓] Cloudflare + Yandex
[✓] Только Cloudflare
[✓] Свои IPv4
```

Перед использованием пользователь видит итоговый список.

# 🕐 Время / NTP

Точный системный clock нужен для TLS.

Поэтому NTP рассматривается как отдельный уровень инфраструктуры.

Менеджер поддерживает IP-first резерв:

```text
DNS Manager
   │
   ├── NTP profile
   ├── IP fallback
   └── независимость от DoH
```

Это особенно важно при запуске роутера, когда DNS/DoH ещё не готов.

Рекомендуемый интерфейс:

```text
🕐 ВРЕМЯ / NTP

  Текущее время:
  ✓ Система синхронизирована

  IP-first:
  ✓ ВКЛ

  Профиль:
  Cloudflare / NIST / ВНИИФТРИ / Google

  [✓] Проверить
  [✓] Применить
  [✗] Отмена
```

# 🚫 Anti-Stub / Bogus NXDOMAIN

DNS Manager может использовать статические IP-заглушки в `dnsmasq`.

Задача:

```text
Провайдер
   │
   └── вместо реального IP
          │
          ▼
       заглушка
          │
          ▼
      dnsmasq
          │
          └── отбрасывает известную заглушку
```

Список заглушек должен быть **консервативным**.

Не рекомендуется автоматически считать все необычные IP заглушками: некоторые сети фильтрации могут возвращать реальные IP.

Поэтому новый IP-заглушка должен добавляться осознанно.

# 💾 Транзакции и rollback

Перед изменениями менеджер создаёт snapshot.

Логика:

```text
DISCOVER
   ↓
PLAN
   ↓
CONFIRM
   ↓
SNAPSHOT
   ↓
APPLY
   ↓
VERIFY
   │
   ├── ✓ успех → COMMIT
   │
   └── ✗ ошибка → ROLLBACK
```

### При ошибке

Пользователь видит:

```text
🩷 ОБНАРУЖЕНА ОШИБКА

✓ Наши изменения откатированы.
✓ Чужие объекты не брались под управление.
✓ Состояние проверено повторно.
```

# 🔒 Ownership

DNS Manager должен отличать:

```text
dns_manager=1
```

от:

```text
foreign
unknown
```

Это особенно важно для `https-dns-proxy`.

Например:

```text
DoH #1
  owner: DNS Manager
  resolver:
  port:

DoH #2
  owner: foreign
  resolver:
  port:
```

При удалении:

```text
🟢 Наш объект → можно удалить
🟡 Чужой объект → не трогать
🩷 Неизвестный → не трогать
```

# 🔌 Порты DoH

Портовая политика:

1. посмотреть уже занятые порты;
2. посмотреть UCI `https-dns-proxy`;
3. определить владельцев;
4. построить **полный план** портов;
5. проверить отсутствие дублей;
6. только после этого изменить UCI.

Нельзя делать:

```text
слот 1 → изменить порт
слот 2 → изменить порт
слот 3 → изменить порт
```

и каждый раз заново вычислять свободный порт.

Правильно:

```text
CURRENT STATE
      ↓
PORT MAP
      ↓
COMPLETE PLAN
      ↓
VERIFY UNIQUE
      ↓
APPLY ONCE
```

Это делает применение идемпотентным и предотвращает каскад:

```text
5053 → 5054 → 5055 → 5056
```

при каждом повторном запуске.

# 🧹 Удаление

Пункт удаления не должен означать:

> «вернуть роутер в заводское состояние».

Он означает:

> «удалить только то, чем владеет DNS Manager».

То есть:

```text
✓ наши DoH
✓ наши записи dnsmasq
✓ наши firewall rules
✓ наши manager-файлы
✓ наши NTP-файлы
```

Но:

```text
✗ чужой DoH
✗ Zapret
✗ VPN
✗ Tailscale
✗ вручную добавленное правило
✗ неизвестная конфигурация
```

остаются.

# ⚠️ Важные ограничения

## DNS ≠ универсальный обход

Не следует считать любой DNS из категории `bypass` гарантированным обходом любой блокировки.

Реальный результат зависит от:

- типа блокировки;
- сети провайдера;
- региона;
- конкретного сервиса;
- текущего состояния DNS;
- состояния самого DoH endpoint.

Поэтому менеджер **тестирует серверы перед рекомендацией**.

## Не все DNS одинаковы

Например:

```text
⚡ быстрый
🛡 безопасный
🔐 приватный
🧹 adblock
👨‍👩‍👧 family
🌍 geo
🚀 bypass
🎮 gaming
```

— это разные назначения.

Поэтому автоматический подбор должен учитывать профиль.

# 🧱 Что DNS Manager НЕ делает

DNS Manager не должен:

- удалять чужие DNS;
- удалять Zapret;
- удалять VPN;
- удалять Tailscale;
- переписывать `/etc/hosts` без необходимости;
- отключать TLS-проверку;
- использовать `curl -k` для обхода ошибок сертификата;
- занимать чужие порты;
- молча переписывать чужой `force_dns`;
- выдавать мёртвые DNS за рабочие;
- считать DNS единственным методом обхода блокировки.

# 🔄 Обновление без изменения конфигурации

DNS Manager разделяет два независимых процесса:

```text
ОБНОВЛЕНИЕ ПРОГРАММЫ
        ≠
ИЗМЕНЕНИЕ РОУТЕРА
```

Проверка GitHub нужна для получения новой версии менеджера. Она не должна сама по себе менять DNS, DoH, dnsmasq, NTP, firewall или другие настройки.

Любое изменение роутера проходит через:

```text
READ → PLAN → CONFIRM → SNAPSHOT → APPLY → VERIFY
                                      │
                                      └── ошибка → ROLLBACK
```

# 🚀 Главное

DNS Manager строится вокруг простой идеи:

```text
              БОЛЬШОЙ КАТАЛОГ DNS
                       │
                       ▼
                 ЖИВОЙ ТЕСТ
                       │
                       ▼
              КЛАССИФИКАЦИЯ
                       │
                       ▼
              УМНЫЙ ВЫБОР ПУЛА
                       │
                       ▼
             6 × DoH параллельно
                       │
                       ▼
                    dnsmasq
                       │
              ┌────────┴────────┐
              │                 │
          обычные DNS        .ru/.su/.рф
              │                 │
          DoH-пул            RU DNS
              │                 │
              └────────┬────────┘
                       ▼
                    КЛИЕНТ
```

**Большой каталог нужен для выбора и резервирования. Не нужно запускать весь каталог одновременно.**

Именно это позволяет совместить:

**скорость + устойчивость + разные назначения DNS + автоматизацию + безопасную работу на уже настроенном роутере.**
